# نصب‌کننده‌ی میکروتیک

**نصب میکروتیک RouterOS روی سرور لینوکس با یک دستور.**
نصب با Docker و انتشار فقط پورت TCP شماره‌ی `36666` برای Winbox؛ همچنین نصب CHR به‌صورت گزینه‌ای مستقل و جداگانه در دسترس است. دستور کوتاه `mik-help` منو را دوباره باز می‌کند.

## نصب سریع

این دستور را روی سرور با کاربر **root** (یا کاربری که `sudo` دارد) اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AmiRaiZo/MIKROTIK/main/install.sh)
```

بعد از اولین اجرا، از هر جای SSH می‌توانید منو را دوباره باز کنید:

```bash
mik-help
```

> دستور را دقیقاً به شکل `bash <(curl ...)` اجرا کنید. اجرای `curl ... | bash` کار نمی‌کند، چون نصب‌کننده از شما سؤال می‌پرسد.

## پورت باز در نصب Docker

نصب‌کننده فقط همین یک پورت را روی سرور منتشر می‌کند:

| سرویس | پورت سرور | پورت داخل کانتینر |
|---|---:|---:|
| Winbox | TCP `36666` | TCP `8291` |

این جدول، Port Mapping اولیه‌ی Docker را نشان می‌دهد. برای انتشار پورت‌های دیگر در حالت Docker از گزینه‌ی **6) Manage public ports** در منوی `mik-help` استفاده کنید.

### مدیریت پورت‌های عمومی

از `mik-help` گزینه‌ی **6** را بزنید. می‌توانید پورت عمومی سرور، پورت مقصد داخل MikroTik و پروتکل TCP یا UDP را وارد کنید. اگر پورت مقصد را خالی بگذارید، همان شماره‌ی پورت عمومی استفاده می‌شود.

مثال: پورت عمومی UDP شماره‌ی `51821` به UDP شماره‌ی `51821` داخل MikroTik منتقل می‌شود؛ در نتیجه اتصال به `SERVER_IP:51821` به RouterOS می‌رسد. از همین منو می‌توانید پورت را ببندید یا فهرست پورت‌های بازشده را ببینید.

این قابلیت با قواعد NAT و فایروال میزبان کار می‌کند و کانتینر را حذف یا بازسازی نمی‌کند؛ تنظیمات RouterOS حفظ می‌شوند و قواعد بعد از راه‌اندازی مجدد سرور یا شروع مجدد کانتینر بازیابی می‌شوند. پورت باید در فایروال پنل ارائه‌دهنده نیز مجاز باشد و سرویس/قانون ورودی متناظر در RouterOS فعال باشد. این قابلیت مخصوص نصب Docker است، نه CHR. قواعد DNAT فقط روی کارت شبکه عمومی IPv4 سرور که از مسیر پیش‌فرض شناسایی می‌شود اعمال می‌شوند؛ بسته‌هایی که از bridge داخلی Docker می‌آیند وارد DNAT نمی‌شوند و اتصال‌های خروجی MikroTik به IP عمومی میزبان دوباره به خود کانتینر برنمی‌گردند.

گزینه‌ی **4** کانتینر را با همین تنظیم تک‌پورت دوباره می‌سازد. تنظیمات قبلی RouterOS پاک می‌شود؛ پس قبلش دستور `/export file=backup` را اجرا کنید.

## بعد از نصب

**Docker:** پورت TCP شماره‌ی `36666` روی سرور به Winbox با TCP `8291` داخل RouterOS وصل می‌شود و Docker پورت دیگری منتشر نمی‌کند.

**CHR:** نصب‌کننده کل دیسک سرور را با ایمیج CHR جایگزین می‌کند. قبل از ادامه از اطلاعات نسخه‌ی پشتیبان بگیرید و مطمئن شوید از طریق کنسول/VNC پنل ارائه‌دهنده به سرور دسترسی دارید. CHR مستقیماً از شبکه‌ی سرور استفاده می‌کند.

**خروج از کنسول Docker** بدون متوقف کردن کانتینر: کلید `Ctrl+P` و بعد `Ctrl+Q` را بزنید.
**برگشت دوباره به کنسول:**

```bash
docker attach livekadeh_com_mikrotik7_7
```

## پیش‌نیازها

- یک VPS یا سرور با **Ubuntu، Debian، CentOS یا Fedora**
- دسترسی root یا `sudo`
- اینترنت روی سرور
- برای نسخه‌ی Docker حداقل **1 گیگابایت رم** و **1 هسته‌ی CPU** کافی است

---

## هشدارها

- در نصب اولیه‌ی Docker، Port Mapping فقط پورت TCP شماره‌ی `36666` برای Winbox است؛ گزینه‌ی 6 امکان Forward پورت‌های بیشتر را جداگانه فراهم می‌کند.
- نصب CHR دیسک سرور را پاک می‌کند و سیستم‌عامل را جایگزین می‌کند؛ قبل از نصب نسخه‌ی پشتیبان بگیرید و از دسترسی کنسول/VNC پنل ارائه‌دهنده مطمئن شوید.
- CHR از Port Mapping داکر استفاده نمی‌کند؛ سرویس‌های آن را با فایروال RouterOS و فایروال ارائه‌دهنده ایمن کنید.
- هرگز رمز عبور پیش‌فرض را روی سروری که از اینترنت در دسترس است نگه ندارید.
